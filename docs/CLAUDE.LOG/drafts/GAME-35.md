- **起因**：plan Task C1（taskboard GAME-35）。B1 的 `pickDemo`／`playbackMs` 與 A2 的 GameBoard `marks`／`trail` 已就緒，首頁要有「示範怎玩」入口與播放對話框。
- **裁定（使用者）**：無（沿用 spec D1–D8）。派工時主 session 放行一個 i18n 例外：`demo.mapInfo` 原為「{difficulty}　第 {n} 張」，與 spec §5.2 不符，改為「第 {n} 張地圖・{difficulty}難度｜退回 {k} 次」；其餘 demo.* 措辭已與 §5.3 相符，未改。
- **做法**：`useDemoPlayback` 先把整段 trace 展開成「畫面＋停留毫秒」的清單（`buildDemoFrames`），再用一個 `setTimeout` 逐張走，所以 `stop()` 只需清一個計時器、`start()` 重入必然只剩一組，且總長由建構保證等於 `playbackMs`（測試對手寫 trace 與 fixture 的真實 trace 都比對 `framesMs === playbackMs`）。每段退回的 `branchPauseMs + branchMsgMs` 掛在該段最後一個 `unplace` 之後：先停在「往回退」並只留分歧點藍框，再換「從 m 改走另一條路」；m 由向前看整段 `unplace` 的最後一格得出（m = 最後收回的數字 − 1），所以第一格收回時就能標出分歧點。卡住時被拒的非 `used` 鄰格標 reject、`cells` 聯集標 trap（同格兩者都有時 reject 優先，保留 ✕）。「依序往下填」只在前一則不是 progress、或與上次相差 ≥ 12 時換字；因 100 內相鄰質數最大間距是 8，實際上每個質數提示之後的第一個非質數就會換字，12 步規則只在理論上生效，行為仍符合 §5.3「不必每步換字」。
  DemoDialog 沿用 BsModal（預設寬度；在 1280 寬 500px 的對話框內棋盤 440px，320 寬時以 `:deep(.pt-board)` 把 `--cell` 改成 `clamp(22px, (100vw − 64px)/11, 40px)` 扣掉對話框邊距，不碰 board.scss）。開啟時 `store.load()` 後同步 `pickDemo`（B1 實測平均 11.3ms < plan 門檻 30ms，**採同步，不分批**）；用 generation 計數避免關閉後才回來的載入啟動舊播放；題庫缺失、載入失敗或 `pickDemo` 丟錯都只顯示一行 `demo.loadFailed`。說明區固定高度（窄螢幕 11.5rem、≥576px 8.5rem）＋ `aria-live="polite"`。棋盤用 GameBoard `readonly`、`mode="direct"`（`touch-action: pan-y`，對話框內可捲動）。首頁按鈕放在規則卡標題列、收合切換鈕之外，收合時仍可見；題庫載入中停用並 `aria-busy`。示範只讀題庫，不碰 progress／records／存檔／ui 偏好。
