## 2026-10-25 GAME-24（U-B1）遊戲頁：頂列、操作列分主次與「更多」選單、下一個數字、pending 移入資訊列（spec：docs/superpowers/specs/2026-10-25-ui-refresh.md §4.1–§4.3、§5.1）

- **頂列取代 StatusBar 的地圖／難度／計時**：棋盤上方一列「← 首頁」「地圖 #0001・簡單」「計時」。首頁用 `RouterLink`（外觀是按鈕、`data-action="home"`），因為它是導覽而不是動作，螢幕報讀器會念成連結。離開時不另外存檔：`usePlaySession` 在元件 scope dispose 時的 `teardownGame()` 本來就會 `flushSave()`，路由離開會卸載 PlayView，所以 debounce 中的最後一步不會丟；這點用單元測試與 e2e（填一格立刻按首頁，再按繼續上次）守住（Review Focus 2）。
- **操作列只留「復原」「提示」「更多」**：移除 `toggleMode`（模式切換只剩 InputModeToggle）與 `clear`（接續模式等於復原、指定模式等於數字鍵盤的清除，R33 結案）。「更多」是自製的小選單而不是 Bootstrap dropdown：本專案不載 Bootstrap JS。開啟時焦點移到第一項，所以鍵盤事件不會落到棋盤（棋盤只聽自己的 keydown，Review Focus 1）；Esc 與選項點選後焦點回觸發鈕，選項觸發的對話框關閉時 BsModal 會把焦點還給觸發鈕；點外面（capture 階段的 pointerdown）或 Tab 離開則關閉但不搶焦點。選單往上展開，因為操作列在頁面底部，手機上往下會被切掉。
- **資訊列**：接續模式顯示「下一個：n」（n = head + 1，head = 100 時不顯示），指定模式改顯示 pending（從 NumberPad 移出，NumberPad 只剩按鍵）。數字用 Fredoka 大字。
- **超過 100 的鍵仍要有回饋（Review Focus 5）**：原本被拒的數字只 shake 選取格，沒選格時完全沒反應。PlayView 包住 NumberPad 的 digit 與棋盤的數字鍵，比較呼叫前後的 pending：接受的數字一定讓 pending 變長，沒變就是被拒，於是遞增 `rejectSeq`，StatusBar 讓 pending 框紅框閃 300ms 並在 `role="status"` 內放一段只給報讀器的說明。這是 StatusBar 介面上多出的可選 prop（plan 列的五個 props 之外），選這個做法是因為不用改 `usePlaySession`（禁區）。
- **焦點環殘留（GAME-23 留下的問題）**：PlayView 掛載時聚焦棋盤（讓方向鍵、數字鍵立刻能用），GameBoard 的 `focus()` 與 pointerdown 一律用 `focus({ preventScroll: true, focusVisible: false })`，所以載入和點格都不會出現藍框。代價是 Chrome 不會因為在已聚焦的元素上按鍵就把它改成 focus-visible，實測按 Tab（棋盤攔下來切模式）後仍不符合 `:focus-visible`。所以 GameBoard 在棋盤本身收到非修飾鍵、且目前不是 focus-visible 時，先 blur 再以 `focusVisible: true` 重新聚焦（對已聚焦元素直接 focus 是 no-op）。e2e 驗證：載入後與點格後不符合 `:focus-visible`，按 Tab 後符合，Shift+Tab 離開再 Tab 回來也符合。
