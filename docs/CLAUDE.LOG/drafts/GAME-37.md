## 2026-10-25 GAME-37 修正 GAME-32 回歸：格子數字多出前後空白（backlog R53(a)）

- **起因**：GAME-32 把 BoardCell 非 trail 的按鈕內容寫成 `` {{ ` ${n} ` }} ``，理由是「維持改動前的 ' 7 ' 文字節點」。這個前提是錯的：改動前模板是按鈕內單獨一行 `{{ value > 0 ? value : '' }}`，Vue 編譯會移除元素邊界上只含空白的文字節點，實際輸出是 `7`，沒有空白。多出的空白讓 `e2e/04-solution-assisted.spec.ts` 的 `hasText: /^100$/` 比對原始 textContent 而找不到格子（桌機、行動各一次）。
- **為什麼單元測試沒抓到**：GAME-32 的測試把錯誤前提直接寫成期待值（斷言 `' 7 '`、`'  '`），實作與測試共用同一個錯誤假設，互相印證；沒人回頭對照 bc82725 的真實渲染輸出。Playwright 頁面快照顯示的文字會正規化空白，也看不出差異，只有 regex 比對 textContent 的 e2e 才暴露。
- **做法**：數字改由一個內部函式式元件輸出：非 trail 回傳純字串（Vue 產生單一文字節點，無 Fragment 空錨點），trail 回傳 `span.pt-num-corner`。DOM 與 bc82725 一致，trail 行為不變（數字仍在高 z-index 的角落 span 內）。
- **守門**：BoardCell 測試改斷言 `'7'`／`''`，並加按鈕 `childNodes` 只有一個文字節點的斷言；先還原實作確認該案失敗。e2e 04、15、16 皆過。
