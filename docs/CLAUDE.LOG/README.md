# 工作日誌寫法

每個月一個檔 `YYYYMM.md`。重要工作完成後追加一段，**記「為什麼」比「做了什麼」重要**，不逐行描述程式碼。

**分支內不改月檔**：多個分支在檔尾各追加一段，合併一定衝突。在分支上工作時把那一段寫成 `drafts/<分支或任務編號>.md`（內容就是月檔的一段，含 `## ` 標題），主 session 合併時併入月檔並刪草稿，與合併同一個 commit。

段落標題：`## YYYY-MM-DD <主題>（spec：<路徑>）`，內容固定七項，沒有的項目寫「無」：

- **起因**：為什麼要做、從哪裡來（backlog 編號、使用者要求、盤點紅燈）。
- **裁定（使用者）**：使用者拍板的取捨與理由。
- **做法**：架構層面的選擇，哪些刻意不動。
- **守門**：測試檔數／案數的前後數字、新增案例、DoD 結果。
- **流程**：spec → 裁定 → 派工方式（單 agent／worktree 平行／workflow 哪一層）→ 合併順序與 commit。
- **踩坑**：這次遇到的環境或工具問題與解法，下次要避開的。
- **遺留**：回寫 backlog 的編號。
