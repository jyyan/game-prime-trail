# Prime Trail 操作提示（PC／Mobile 操作指引）設計

- 狀態：**定稿**（使用者 2026-10-25 確認，含規劃者決定）
- 日期：2026-10-25
- 上位文件：`docs/superpowers/specs/2026-10-24-prime-trail-design.md`（下稱「主 spec」）§7.3（操作語意）、§9（版面）；`docs/superpowers/specs/2026-10-25-ui-refresh.md`（下稱「UI spec」）§4.1（遊戲頁頂列）。本文定稿後，主 spec §9 的頂列描述補上「？」按鈕。

## 1. 為什麼

使用者回報：第一次玩的人不知道可以用方向鍵（電腦）或拖曳（手機）一路連填。主 spec §7.3 定義的操作都已實作，但畫面上沒有任何地方告訴玩家。目標是讓第一次玩的人「看一眼就會」，不是一本說明書。

## 2. 使用者裁定（2026-10-25）

| # | 項目 | 裁定 |
|---|---|---|
| H1 | 首次提示何時消失 | 玩家成功操作一次就自動消失，之後不再主動出現 |
| H2 | 找回說明 | 遊戲頁頂列放「？」按鈕，點開完整操作說明 |

## 3. 目標／不做／失敗條件

- 目標：首次進遊戲頁的玩家在第一步之前就看到「依自己裝置」的關鍵操作；任何時候都能從頂列「？」找回完整說明。
- 不做：互動式教學（逐步導覽、遮罩聚光）；首頁加說明（首頁規則卡講遊戲規則，本文只講操作）；改任何操作語意或鍵位；多語系。
- 失敗條件（即使功能「能動」也算失敗）：提示擋住棋盤格或讓棋盤在 320px 寬溢出／被裁切；提示消失後每次進頁又跑出來；提示內容和裝置不符（手機看到「按方向鍵」）；破壞既有 e2e 的版面斷言。

## 4. 首次提示

### 4.1 何時出現

- 進入遊戲頁、題目載入完成（`status` 為 ready 且盤面已顯示）時，若本機尚未記錄「看過提示」，在**頂列與棋盤之間**顯示一張提示卡。
- 已過關的局（盤面鎖定）不顯示。
- **規劃者決定**：恢復的存檔若已有玩家步數（`state.steps > 0`），視為已會操作：不顯示，並直接寫入 `controlsHintSeen: true`（功能上線前就在玩的人不會被打擾）。
- 「看過」記在 localStorage `prime-trail:v1:ui` 的 `controlsHintSeen: true`（與首頁 `rulesCollapsed` 共用同一物件，讀寫一律先讀再合併，不得覆蓋對方欄位）。換裝置或清除資料會再出現一次，可接受。
- **規劃者決定**：把 HomeView 內嵌的 `ui` 讀寫抽成共用 helper（例如 `src/composables/useUiPrefs.ts`，`read()`／`merge(patch)`），HomeView 改用它，行為與既有測試不變。storage 損毀或讀不到時視為「沒看過」；寫入失敗（隱私模式）不報錯，當次照常隱藏。

### 4.2 何時消失（H1）

任一條件成立即隱藏並寫入 `controlsHintSeen: true`：

1. 玩家**自己**成功填入一格（任一模式；接續模式的點、拖曳、方向鍵，指定模式的確認）。「提示」按鈕代填的格不算；撤回、復原、拖回退一步、清除這類**不填入**的成功操作也不算。
   - **規劃者決定**：允許在 `usePlaySession.ts` 新增一個「玩家填入成功」的通知（callback 或遞增計數 ref），在既有 place 成功路徑觸發；不改任何操作語意、不改 `src/core/**`。不得用 `grid`／`steps` 的 watcher 推測（提示、撤回、重新開始、恢復存檔都會改它們）。
2. 玩家按提示卡上的關閉鈕（×，`aria-label` 走 i18n）。**規劃者決定**：給一個不必操作也能關掉的出口。
3. 玩家打開「？」說明。**規劃者決定**：看了完整說明就等同看過；在**打開時**寫入並隱藏。

被拒絕的操作（shake）不算成功，提示保留。

### 4.3 內容（依裝置與目前輸入模式）

裝置判斷（**規劃者決定**）：`matchMedia('(pointer: coarse)')` 為真視為觸控，否則視為滑鼠＋鍵盤；不嗅探 user agent。判斷在提示顯示時做一次即可。

內容依目前輸入模式（`state.inputMode`）選，模式切換時即時換文字：

| | 觸控 | 滑鼠＋鍵盤 |
|---|---|---|
| 接續模式 | 從龍頭往相鄰格**拖曳**就能一路連填；拖回上一格可退一步 | 點棋盤後按**方向鍵**延伸一格；**Backspace** 撤回；**Tab** 切換模式 |
| 指定模式 | 點一格，用下方數字鍵盤輸入，按「確認」 | 點一格，打**數字**後按 **Enter**；方向鍵移動選取格 |

文字最後附一句「隨時可按右上角 ？ 再看說明」。實際措辭由實作者寫進 i18n，意思不變、每格一到兩行。

### 4.4 外觀

- 卡片用 UI spec §3 token（`--pt-surface` 底、`--pt-text` 字、`--pt-radius-card`；可用 `--pt-primary` 左側色條）；對比 ≥ 4.5:1 並登記到 `scripts/check-contrast.ts`。
- 出現時 150–300ms 淡入，`prefers-reduced-motion: reduce` 時不動畫。
- 卡片在文件流中（不疊在棋盤上），320px 寬時棋盤仍完整可見、無水平捲動；關閉後版面上移即可，不需動畫。
- `role="note"`（或 `status`），螢幕報讀可讀到；不搶焦點，不攔截棋盤鍵盤事件。

## 5. 「？」完整說明（H2）

- 頂列最右側（計時之後）新增「？」按鈕，遊戲頁 ready 時一律顯示（含已過關的局）：`data-action="help"`、`aria-label`「操作說明」、觸控目標 ≥ 44×44px；320px 寬時頂列不得換行到擠壓地圖標題以外的程度（標題可省略號截斷）。
- 點開為對話框（沿用 `BsModal`，Esc／× 關閉、焦點回到「？」）。
- 內容兩段：「手機／平板（觸控）」與「電腦（滑鼠＋鍵盤）」，**兩段都列出**（觸控筆電兩種都能用），目前裝置那段排在前面。每段再分「接續模式」「指定模式」，涵蓋主 spec §7.3 的全部操作：
  - 觸控：點相鄰格延伸、拖曳連填、拖回退一步；指定模式點格＋數字鍵盤＋確認、清除。
  - 鍵盤：方向鍵、Backspace／Delete、Tab 切換模式、Ctrl/Cmd+Z 復原、數字鍵＋Enter、方向鍵移動選取。
  - 共用：「復原」「提示」與「更多」選單裡的看解答／匯出 PDF／重新開始各一句。
- 鍵名以 `<kbd>` 呈現（樣式用 token，不依賴未匯入的 Bootstrap partial；`bootstrap-partials` 防漂移測試必須維持綠）。
- 說明開著時棋盤不收鍵盤事件（沿用 BsModal 的行為）。

## 6. 約束

- CJK 字串只能放 `src/i18n/zh-TW/<ns>.ts`；**規劃者決定**新增命名空間 `help.ts`。
- 不改 `src/core/**`、題庫、存檔格式（`prime-trail:v1:L…` 局存檔）、路由與操作語意。
- 既有 e2e 會被首次提示改變版面：`e2e/helpers.ts` 以 `addInitScript` 在 `prime-trail:v1:ui` 缺 `controlsHintSeen` 時合併寫入 `true`（不覆蓋既有欄位，如 12-home-ui 寫的 `rulesCollapsed`）；新的操作提示 e2e 以明確選項（例如 `openPlay(page, …, { controlsHint: true })` 或不呼叫該 init script）從乾淨狀態開始。

## 7. 驗收

- DoD 三條全綠；`pnpm test:e2e` 全綠；對比腳本全綠。
- 單元測試：首次顯示；玩家填一格後消失且寫入 storage；提示按鈕代填不會讓它消失；被拒操作不消失；× 與「？」都會讓它消失；已寫入就不顯示；與 `rulesCollapsed` 共存不互相覆蓋；觸控／非觸控與兩種模式各自顯示正確文字（mock `matchMedia`）。
- e2e：桌機（滑鼠）看到鍵盤版提示、按方向鍵延伸一格後提示消失、重新整理不再出現；行動（`hasTouch`、`isMobile`）看到拖曳版提示、拖曳一格後消失；「？」可用鍵盤開關且焦點回到按鈕；320px 寬提示顯示時無水平捲動、棋盤底緣未裁切。
- 375／1280 px 截圖（首次提示、說明對話框）附在 CLAUDE.LOG。
