# Prime Trail「示範怎玩」AI 試錯播放、死路標示與完成連線設計

- 狀態：**定稿**（使用者 2026-10-25 確認，含規劃者決定）
- 日期：2026-10-25
- 上位文件：`docs/superpowers/specs/2026-10-24-prime-trail-design.md`（下稱「主 spec」）§1.3（非目標）、§5（solver）；`docs/superpowers/specs/2026-10-25-ui-refresh.md`（下稱「UI spec」）首頁規則卡；`docs/superpowers/specs/2026-10-25-controls-help.md`（操作說明，與本文分工見 §3）。
- 試作：2026-10-25 在本機做過一次性試作（不進 repo），使用者看過後裁定「照這個模式實作」。本文的 AI 規則、時間與文字即來自該試作與使用者回饋。

## 1. 為什麼

首頁「怎麼玩」規則卡只有三行字，新玩家讀完仍不知道實際怎麼走，更不知道「卡住要退回分歧點」是這個遊戲的核心手感。使用者要的是：新玩家看規則時按一顆按鈕，看 AI 在真的盤面上一格一格走、走進死路、說出卡住的原因、退回分歧點改走別條路，看完就懂走法與退回。

## 3. 目標／不做／失敗條件

- 目標：首頁按「示範怎玩」→ 對話框內自動播放一張簡單難度地圖的完整解題過程，含 2–4 次退回，每次卡住都有看得懂的中文原因與盤面標記，播完停在完成盤面。
- 不做：遊戲頁的示範按鈕；依玩家目前盤面求解或給提示（主 spec §5.6 不變）；暫停、速度調整、逐步前後翻；解說語音；進階／挑戰難度的示範；改 `src/core/solver.ts`。
- 目標（D9–D11）：正式遊戲簡單難度中，玩家的路線一旦注定走不完，立刻在盤面標出來，見 §6。
- 目標（D8）：示範播完、以及正式遊戲過關後，棋盤上畫出 1→100 的連線，見 §5.4。
- 與操作說明（controls-help spec）的分工：本功能講「規則與解題思路」，不講按鍵或觸控操作。
- 失敗條件（即使「能動」也算失敗）：
  - 卡住時只說「走不下去」而沒講原因，或原因與盤面不符（例如說某格被困，但盤面上那格其實還有路）。
  - 一次示範沒有任何退回，或退回多到播超過約 6 分鐘。
  - 關掉對話框後計時器仍在跑、或重開時兩段播放疊在一起。
  - 寫入任何進度、紀錄、存檔或 `ui` 偏好（示範不得影響玩家資料）。
  - 打開對話框讓首頁明顯卡頓（主執行緒長時間被算圖佔住）。
  - 320px 寬時棋盤被裁切或出現水平捲動。

## 4. 示範 AI（`src/core/demo-solver.ts`，新檔，純 TS）

刻意與 `solver.ts` 分開：solver 剪枝太強，幾乎不會退回；示範 AI 要「像人」，用人看得懂的規則，才會出現看得懂的退回。主 spec §1.3「在瀏覽器內跑 solver」的非目標**維持**，本模組不是 solver、不用於求解玩家盤面；本文定稿時在主 spec §1.3 該條補一句「首頁示範用的 demo-solver 除外，見 `2026-10-25-demo-playback.md`」。

### 4.1 題面

一律用該地圖的**簡單**難度題面（`derivePuzzle(level, 'easy')`：1 與 25 個質數全部顯示）。

### 4.2 搜尋

DFS，從 1 依序放 2…100，每步的候選是 head 的四方向相鄰格。候選 x 放數字 n 的條件，依序檢查，第一個不成立的就是該格的「原因」：

| 原因代碼 | 條件（不成立即拒絕） |
|---|---|
| `used` | x 未填過 |
| `otherGiven` | x 不是另一個數字的固定格（given） |
| `givenElsewhere` | 若 n 是 given，x 就是它的格 |
| `needPrime`／`notPrime` | `grey[x] === isPrime(n)` |
| `far` | 下一個 given v 仍走得到：`manhattan(x, cell(v)) ≤ v − n` |
| `trap`／`twoEnds` | 放下後沒有空格四面被圍（可走的鄰格數為 0）；可走鄰格數為 1 的空格最多一個（`trap` 列出鄰格數 0 的格，否則 `twoEnds` 列出鄰格數 1 的格）。「可走鄰格」= 未填的鄰格，加上新 head |
| `split` | 放下後所有空格與新 head 連通（不連通時列出 head 走不到的那一塊） |

- 通過全部檢查的候選才會真的「走進去」並出現在播放裡；被檢查擋下的候選不播（AI「看出來」不能走）。
- 候選排序：可走鄰格數少者優先（Warnsdorff），同分依 上、右、下、左。
- 某一步沒有任何候選、而且這一步一個都沒試過時，即為**卡住**：記錄一筆卡住事件，內含 head **每個**鄰格各自的原因（每格各取它第一個不成立的檢查；`trap`／`twoEnds`／`split` 對該格做假設性放置後判定；`used` 也記，但播放時不列）與 `trap`／`twoEnds`／`split` 涉及的格子。之後一路退回，直到某個數字還有沒試過的候選。
- 退回途中，某一步的候選已經試完（試過至少一個）而繼續往回退時，**不**另記卡住事件，只是同一段退回的延續。因此每段退回（連續的 `unplace`）前面恰好有一筆卡住事件，「退回段數」＝卡住事件數＝連續 `unplace` 段數。
- 卡住時多個鄰格各自標出被困／被切斷的格子，盤面紅框取**聯集**。
- 試作數據（300 張地圖）：此組規則下每張圖退回段數中位數約 21、全程事件數中位數約 260，約 1/6 的地圖落在 §4.3 的範圍內。GAME-33 以完整條件（含播放總長）在 1000 張全庫實測：符合主條件的只有 51 張（約 5%）。

### 4.3 輸出與挑圖

- 輸出事件序列：`place(cell, n)`、`unplace(cell, n)`、`stuck(n, head, reasons)`；一段連續的 `unplace` 為一次「退回」。另附 `backtracks`（退回段數）與是否解完。事件數上限 4000，超過即放棄該圖。
- 挑圖：從 1000 張隨機抽，接受條件為「解完、退回 2–4 段、事件數 ≤ 260、依 §5.3 節奏算出的播放總長 ≤ 360 秒」；最多試 80 張。都不合格時（依 GAME-33 實測約 5% 的接受率，一輪落空機率約 1.5%）改用「解完、退回 1–8 段、播放總長 ≤ 360 秒」中退回段數最接近 2 的那張；仍沒有就再抽 80 張重複一次。不得播放超過 360 秒的圖。播放總長由同一份節奏表（常數）計算，播放與挑圖共用。亂數來源可注入（測試用固定 seed），預設 `Math.random`。（**規劃者決定**：退路與時長上限）
- 預算：試作中一次挑圖在桌機約數十毫秒。實作者量一次中階手機的耗時；若超過約 100ms，改成分批（每算幾張讓出主執行緒）或 Web Worker，二擇一由實作者決定。

## 5. 播放（UI）

### 5.1 入口

- 首頁規則卡加「示範怎玩」按鈕（`data-action="demo"`），**規則卡收合時也看得到**（放在卡片標題列或卡片底部，實作者決定）；觸控目標 ≥ 44×44px。
- 按下打開對話框（沿用 `BsModal`，`size="lg"` 或預設由實作者依 320／375／1280 寬試排決定）。題庫未載入時先載入（沿用 `useLevelStore`），載入中按鈕顯示忙碌、不重複開。題庫缺失或載入失敗：按鈕停用或對話框顯示錯誤一行，不丟例外。

### 5.2 對話框內容

由上而下：一行地圖資訊、說明區、棋盤、「再看一張」按鈕。

- 地圖資訊：「第 N 張地圖・簡單難度｜退回 k 次」。**不顯示**最長一段收回幾格、抽了幾次、事件數。
- 說明區：`aria-live="polite"`，高度固定到足以放下最多三行原因清單（避免棋盤上下跳動）。
- 棋盤：外觀與遊戲頁一致（同格大小比例、質數格黃底、龍頭格、given 數字樣式）；唯讀、不接受點擊與鍵盤。可重用 `BoardCell.vue` 或另寫唯讀元件，實作者決定，但不得改 `GameBoard.vue` 的互動行為。AI 填的數字用與 given 不同的顏色（試作用 `--pt-primary`）。目前 head 有醒目框。
- 「再看一張」：任何時候都可按，立刻停掉目前播放、換一張圖從頭播。
- 關閉：× 或 Esc（BsModal 既有行為）；關閉時**停止所有計時器**，重開即重新挑圖從頭播。

### 5.3 節奏與文字（D5、D6）

| 階段 | 停留 | 說明區文字（意思不變，措辭進 i18n） |
|---|---|---|
| 開場 | 2.5 s | 從龍頭的 **1** 出發。黃格是質數的位置，一格一格往相鄰的空格填。 |
| 放一般數字 | 1.0 s | 每隔數步更新一次「依序往下填：**n**」，不必每步換字 |
| 放質數 | 1.8 s | **n** 是質數，必須走進黃格。 |
| 卡住 | 3 s ＋ 每條原因 2 s | **n** 之後卡住了，n+1 沒有地方可以放：（清單，每個非 `used` 鄰格一行，前綴「上面／下面／左邊／右邊」）；全部都是 `used` 時改說「四周的格子都已經填過了。」 |
| 退回 | 每格 1.0 s | 往回退，退到 **m**，那裡還有別條路沒試過。 |
| 換路 | 1.2 s ＋ 1.8 s | 從 **m** 改走另一條路。 |
| 完成 | 停住 | **完成！** 1 到 100 全部連起來了，途中退回了 k 次。 |

各原因的文字：

| 代碼 | 文字 |
|---|---|
| `otherGiven` | 這格已經固定是 v |
| `givenElsewhere` | n 的位置早就固定在別處，不是這格 |
| `needPrime` | n 是質數，但這格不是黃格 |
| `notPrime` | 這格是黃格，只能放質數，n 不是質數 |
| `far` | 從這格走到 v 至少要 d 步，但只剩 s 步 |
| `trap` | 填下去，紅框的格子會被四面圍住，再也走不進去 |
| `twoEnds` | 填下去，紅框的格子都只剩一條路進出，變成死胡同；一條路線最多只能有一個死胡同（終點） |
| `split` | 填下去，紅框的空格會被切斷成另一塊，一條路線沒辦法兩邊都走完 |

盤面標記：

- 卡住時：每個被拒的非 `used` 鄰格淡紅底加 ✕ 角標；`trap`／`twoEnds`／`split` 涉及的格子紅色虛線框加淡紅底（D5）。
- 退回時：被收回的格子短暫淡紅底、數字換成 ✕；要退到的分歧點（m 所在格）藍色虛線框，直到換路文字結束。
- 顏色用 UI spec §3 token；新增的淡紅底若會襯字，對比 ≥ 4.5:1 並登記到 `scripts/check-contrast.ts`。✕ 是文字字元不是圖示，可用。

`prefers-reduced-motion: reduce`：格子底色切換不做過渡動畫；停留時間不變（節奏是內容，不是動畫）。

### 5.4 完成連線（D8，示範與正式遊戲共用）

比照 PDF 解答頁（`src/pdf/renderPuzzlePdf.ts` 的 `drawSolutionPage`）：

- 依完成盤面的 1→100 順序，以一條折線連接相鄰兩數所在格的**格心**；線色 `rgb(52,101,164)`（同 PDF 的 `PATH_RGB`，若改成 token 須與之同色系），線寬約格寬的 8%，圓角接頭與端點。
- 畫線時，每格數字縮小並移到格子**左上角**，讓線條看得見；質數格黃底、龍頭格底色照舊。
- 線畫在格子底色之上、數字之下（數字不被線蓋住）；不攔截指標事件。
- 用一個共用的 SVG 疊層元件（例如 `src/components/board/TrailLine.vue`，輸入為 `cellOf: 1…100 → cell` 或完成盤面），示範與正式遊戲都用它，不各寫一份。
- 線**一次出現**，不做逐段描繪動畫（PDF 也沒有；**規劃者決定**）。
- **正式遊戲**：盤面狀態為過關（`status === 'won'`）時畫線，線依**玩家自己的盤面**（`grid`）連，不是參考解（主 spec §2.8：玩家解可與參考解不同）。過關彈窗關掉後即可看到；重新整理恢復已過關的局時也要畫。畫線時不顯示龍頭框（D12）。重新開始後線消失。
- **示範**：播到「完成！」時畫線，「再看一張」時消失。
- 「看解答」（`SolutionView`）不在本次範圍，維持現狀（**規劃者決定**：使用者只點名示範盤面與正式遊戲）。
- 本文定稿時在主 spec §6.1（GameBoard）補上這個疊層與過關時的數字位置。

### 5.5 預估長度

1–2 秒一格、約 120–260 個事件、2–4 次卡住，一張圖約 3–6 分鐘。使用者已知悉並以「隨時可以關掉」接受（D4）。

## 6. 正式遊戲的死路標示（D9–D11，僅簡單難度）

目的（使用者原話）：「降低簡單等級的門檻」。新手在簡單難度最常見的挫折，是十幾步前就把某格困死卻不自知，走到最後才發現要大退。早一步標出來，讓新手在犯錯的當下學會「這樣走會困住格子」，正是示範裡要教的同一件事。

### 6.1 判定（共用 `src/core/dead-end.ts`，新檔，純 TS）

把 §4.2 中「放下後會不會注定失敗」的檢查抽成共用模組，示範 AI 的 `far`／`trap`／`twoEnds`／`split` 判定與正式遊戲都呼叫它，不各寫一份。

- 輸入：題面（簡單難度）、玩家盤面 `grid`、目前龍頭 h（主 spec §7.2：「1…h 全已填」的最大 h）。只看路線 1…h：數字 ≤ h 的格視為已走；given 格與玩家填的 > h 的數字視為**未走**（後者在指定模式可能是暫放，不納入判定）。
- 路線 1…h 本身不合法時（有相鄰或質數衝突，即主 spec §8 已標紅的情況）不判定死路，交給既有衝突標示。
- 判定「注定走不完」的條件，任一成立即是死路（都是必要條件的反面，因此不會誤報）：

| 代碼 | 條件 | 標紅的格 |
|---|---|---|
| `far` | 下一個 given v 走不到：`manhattan(head, cell(v)) > v − h` | v 的格 |
| `trap` | 有未走格的可走鄰格數為 0（可走鄰格 = 未走的鄰格，加上龍頭） | 那些格 |
| `twoEnds` | 可走鄰格數為 1 的未走格 ≥ 2 個 | 那些格 |
| `split` | 未走格與龍頭不連通 | 龍頭走不到的那一塊 |
| `noMove` | 龍頭四周沒有任何格能放 h+1（都已走、黃格／非黃格不符、given 對不上） | 無（只在鄰格標 ✕，見下） |

- h = 100（已填滿）時不判定。

### 6.2 顯示

- 死路成立時：**龍頭那一格**（剛填、讓局面注定失敗的那格）標 ✕ 角標；表格中「標紅的格」淡紅底加紅色虛線框；`noMove` 時改為在龍頭四周不能放的鄰格標 ✕（同示範）。
- 盤面下方（或狀態列附近，實作者決定）一行文字說明原因，措辭沿用 §5.3 原因表的意思，主詞改成玩家，例如「填了這格，紅框的格子會被四面圍住，再也走不進去」。`aria-live="polite"`。
- 樣式須與既有衝突標示（`.is-conflict`，紅字紅框實線）**看得出不同**，且不只靠顏色（✕ 與虛線框即為形狀差異）；對比登記到 `scripts/check-contrast.ts`。
- 標示跟著盤面即時重算：玩家退一步、復原、拖回、清除後若不再是死路，標示立刻消失；繼續往前填時只要仍是死路就一直標。
- 進階、挑戰難度不顯示（判定也不必跑）。
- 不設 `assisted`、不寫任何 storage、不改操作語意，被標成死路的局照樣可以繼續填（不阻擋）。
- 首次操作提示卡、過關判定、`findConflicts` 都不受影響。

- 單元測試（`demo-solver`）：
  - 對多張地圖（例如前 50 張），解完時最後盤面滿足主 spec §2.8 `isSolved`。
